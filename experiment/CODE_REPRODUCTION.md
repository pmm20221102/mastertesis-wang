# Code reproduction guide

This guide covers reproducing the software workflow in this repository. It does not reinterpret experimental findings or treat archived outputs as a rerun. The commands assume WSL 2 / Ubuntu 24.04, Python 3.12, ROS 2 Jazzy, and the repository root as the working directory.

For the full raw-data → Khronos → RAG → Nav2 plan-only path and the steps not currently reproducible from this checkout, see [REPRODUCIBILITY_GAPS.md](REPRODUCIBILITY_GAPS.md).

## What can be reproduced from this checkout

| Workflow | Reproduction status | Required inputs |
|---|---|---|
| Python, RAG-builder, map-generation, and interface tests | Runnable from a clean checkout | Python dependencies in `llm-rag/requirements.txt` |
| Khronos/Nav2 bridge compile | Runnable from a clean checkout | ROS 2 Jazzy, `ros-dev-tools`, dependencies declared by `package.xml` |
| RAG builder | Runnable when given the recorded Hospital DSG and semantic-review CSV | DSG and CSV whose SHA-256 values match the defaults file; pinned embedding model revision |
| One natural-language instruction through planner and Nav2 plan-only | Runnable after building the provenance-bearing RAG index and starting the isolated Nav2 stack | Above inputs, Ollama model, built map bundle |
| One archived Nav2 mission in plan-only mode | Runnable from the committed mission and map bundle | Built bridge package and ROS domain dedicated to this run |
| Historical 60-task × 4-condition run | Outputs and runtime inputs are archived; exact batch replay is not currently available from this checkout | The original run driver/code snapshot is not included as an executable entry point; archived `vector_db` lacks the required `build_manifest.json` |
| Historical 49-mission navigation batch | Missions, results, and logs are archived; this is not a clean rerun | Run each mission against the recorded Nav2 setup; archived results are not regenerated by the documentation commands below |

The 60-task output archive is under `task-chain-60/runs/surface-v1-llm2-60x4-20261020/`. Its four prediction files are evidence from the historical run, not a command that re-executes it. The included `run_pipeline_eval.py` is a separate evaluator with different inputs and modes; do not use it as a substitute for the historical 60×4 runner.

## 1. Create the Python environment

From the repository root:

```bash
python3 --version   # expected: Python 3.12.x
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/pip install -r llm-rag/requirements.txt
```

`requirements.txt` pins direct Python dependencies. ROS dependencies are installed separately via `rosdep`; Ollama and embedding model weights plus the Hospital dataset are external inputs.

Install ROS 2 Jazzy and `ros-dev-tools` using the [official Ubuntu installation guide](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html). Install the ROS dependencies declared by this package:

```bash
source /opt/ros/jazzy/setup.bash
export PATH=/usr/bin:/opt/ros/jazzy/bin:/bin
if [ ! -f /etc/ros/rosdep/sources.list.d/20-default.list ]; then sudo rosdep init; fi
rosdep update
rosdep install --from-paths khronos-nav2-bridge/khronos_nav2_bridge --ignore-src -r -y
```

The system-first `PATH` is intentional: ROS Jazzy's Python modules must be loaded with Ubuntu's system Python, not a Conda Python.

## Full Raw-Data Track: TartanGround to Khronos

This optional track starts before the DSG used by the RAG builder. The official [TartanGround documentation](https://tartanair.org/tartanground.html) describes the `Hospital` environment and `diff` robot trajectories. To download the thesis sequence and the front-left sensor modalities, use `tartanairpy`:

```python
import tartanair as ta

ta.init("/path/to/TartanGround_Root")
ta.download_ground(
    env=["Hospital"],
    version=["diff"],
    traj=["P1000"],
    modality=["image", "meta", "depth", "seg", "seg_labels"],
    camera_name=["lcam_front"],
    unzip=True,
    delete_zip=False,
    num_workers=4,
)
```

Point `HOSPITAL_DATASET_ROOT` to the extracted `Hospital/Data_diff/P1000` trajectory directory (or another directory with the same flat layout), containing `image_lcam_front/`, `depth_lcam_front/`, `seg_lcam_front/`, and `pose_lcam_front.txt`. The P1000 metadata records 3,178 poses at a 0.1-second timestep. On the originating WSL workstation, the extracted sequence occupies 4.4 GB and the adapter's read-only audit passed with 3,178 images, 3,178 depth frames, 3,178 segmentation frames, and 3,178 poses.

The validated workstation copy was at `/home/nenlian/Masterthesis-wang/datasets/Hospital-workstation-backup-20261006/tartanground_khronos/dataset/`; this path is local to that machine and is not in Git. Its metadata files had these hashes:

```text
P1000_metadata.json: 7d74b9f8f42668f180b4b058e633f3d3705e1ebe5d178df270584abe64ca0152
seg_label_map.json:  4b2ea5e836c5298c5f506f76ae98aaa6ba38571ef4734eb6efb2c2e5afdd1b34
```

The adapter does not load a separate camera-calibration file: its source defines 640×640 pinhole intrinsics (`fx=fy=320`, `cx=cy=320`), a fixed `base_link` → `camera_optical_frame` transform, and NED → ROS ENU/FLU pose conversion. Treat these as part of the adapter revision and record the checked-out Git commit. The historical Khronos run used `ClosedSetImageReceiver` with TartanGround segmentation labels; the label map/remap configuration must be retained, but no separate online segmentation-model weights are needed for that closed-set path.

Build the TartanGround adapter package from the repository root:

```bash
source /opt/ros/jazzy/setup.bash
export PATH=/usr/bin:/opt/ros/jazzy/bin:/bin
cd khronos/tartanground-tools
rosdep install --from-paths tools/tartanground_khronos_bridge --ignore-src -r -y
colcon build --base-paths tools/tartanground_khronos_bridge --symlink-install
source install/setup.bash
cd ../..
```

Set the dataset root and run the adapter audit before writing a bag:

```bash
export HOSPITAL_DATASET_ROOT=/path/to/TartanGround_Root/Hospital/Data_diff/P1000
ros2 run tartanground_khronos_bridge tartanground_to_ros2bag \
  --dataset-root "$HOSPITAL_DATASET_ROOT" \
  --camera lcam_front \
  --start-frame 0 \
  --num-frames 3178 \
  --fps 10 \
  --output /tmp/hospital-p1000-audit-only \
  --audit-only
```

Expected output includes `data sync: image=3178 depth=3178 seg=3178 pose=3178`. This is a pre-conversion input check; it does not generate a bag. To write a new bag, use a new output path and omit `--audit-only`:

```bash
export HOSPITAL_BAG=/path/to/output/hospital-p1000-lcam-front-10hz
ros2 run tartanground_khronos_bridge tartanground_to_ros2bag \
  --dataset-root "$HOSPITAL_DATASET_ROOT" \
  --camera lcam_front \
  --start-frame 0 \
  --num-frames 3178 \
  --fps 10 \
  --output "$HOSPITAL_BAG"
ros2 run tartanground_khronos_bridge tartanground_audit_bag \
  "$HOSPITAL_BAG" --expected-frames 3178 \
  --json-out "$HOSPITAL_BAG.audit.json"
ros2 bag info "$HOSPITAL_BAG"
```

The bag audit acceptance condition is 3,178 RGB, depth, semantic, and camera-info messages, at least 3,178 `/tf` messages, and at least one `/tf_static` message. Keep the JSON audit and `ros2 bag info` output with the run. The adapter synthesizes timestamps at the selected `--fps`; 10 Hz matches the P1000 metadata timestep. For a new reference run, play the generated bag with an explicit rate:

```bash
ros2 bag play "$HOSPITAL_BAG" --clock --rate 1.0
```

The historical Khronos run does not record its bag playback rate, so `1.0` defines a new reference profile and is not an exact replay of the August 2026 run.

### Portable Khronos Launch

The launch file uses ROS package-share paths for its packaged input, label-space, remap, mapper, and RViz configurations. It accepts `input_config`, `mapper_config`, `rviz_path`, `output_dir`, and `start_visualizer` arguments. Build the Khronos workspace as documented in [`khronos/README.md`](../khronos/README.md), then build the adapter as in the preceding section. In the terminal that will launch the mapper, source both overlays in this order:

```bash

export PATH=/usr/bin:/opt/ros/jazzy/bin:/bin
```

```bash
export KHRONOS_OUTPUT=/absolute/path/to/khronos-output
```

```bash

```

### Build a fresh RAG index and maps from a Khronos run

The RAG index and maps are both generated from the same Khronos output: the RAG builder reads `dsg.json`; map generation reads both `dsg.json` and `mesh.ply`. Neither step requires the historical DSG/mesh hashes or historical map pixels. Use a new output directory for each run:

```bash
export HOSPITAL_KHRONOS_OUTPUT=/absolute/path/to/khronos-output
export HOSPITAL_DSG="$HOSPITAL_KHRONOS_OUTPUT/dsg.json"
export HOSPITAL_MESH="$HOSPITAL_KHRONOS_OUTPUT/mesh.ply"
export HOSPITAL_RUN_OUTPUT="$(mktemp -d "$HOME/hospital-khronos-rebuild.XXXXXX")"
export HOSPITAL_RAG_OUTPUT="$HOSPITAL_RUN_OUTPUT/rag"
export HOSPITAL_MAP_OUTPUT="$HOSPITAL_RUN_OUTPUT/maps"
echo "Run artifacts: $HOSPITAL_RUN_OUTPUT"
test -s "$HOSPITAL_DSG" && test -s "$HOSPITAL_MESH"
sha256sum "$HOSPITAL_DSG" "$HOSPITAL_MESH"
```

Build the provenance-bearing RAG index from this graph. Omitting `--review-csv` means the index uses Khronos semantic labels without human-review overrides; the build manifest records that no override CSV was applied.

```bash
.venv/bin/python llm-rag/RAG/khronos_3dsg_rag/src/main.py \
  --config llm-rag/RAG/khronos_3dsg_rag/config.yaml build \
  --reproducible \
  --dataset hospital-p1000 \
  --input "$HOSPITAL_DSG" \
  --embedding-model paraphrase-multilingual-MiniLM-L12-v2 \
  --embedding-model-revision e8f8c211226b894fcb81acc59f3b34ba3efd5f42 \
  --embedding-device cpu \
  --output "$HOSPITAL_RAG_OUTPUT"
```

Generate four new floor maps from the same Khronos graph and mesh. `--no-manual-topology` tells the generator to use edges in this DSG and skip historical Place-ID overrides. The output includes `dsg_topology_repaired.json`, per-floor maps and reports, and a `manifest.json` with input/output hashes. Grid resolution, extents, and floor elevations remain defined by the checked-in Hospital geometry manifest and `FLOOR_HEIGHTS`; map occupancy is recomputed from this run's Place and mesh data.

```bash
.venv/bin/python experiment/map-generation/generate_khronos_only.py \
  --dsg "$HOSPITAL_DSG" \
  --mesh "$HOSPITAL_MESH" \
  --output "$HOSPITAL_MAP_OUTPUT" \
  --no-manual-topology
test -s "$HOSPITAL_RAG_OUTPUT/build_manifest.json"
test -s "$HOSPITAL_MAP_OUTPUT/manifest.json"
```

Create a run-specific Nav2 bundle and defaults profile. This retains the reviewed directed transition template, updates every floor map path/hash, checks all transition endpoints and the initial pose against the new map's free cells, and pins the defaults to the RAG build inputs:

```bash
.venv/bin/python experiment/map-generation/package_nav2_run.py \
  --maps-manifest "$HOSPITAL_MAP_OUTPUT/manifest.json" \
  --rag-build "$HOSPITAL_RAG_OUTPUT" \
  --output "$HOSPITAL_RUN_OUTPUT/nav2-profile"
export HOSPITAL_NAV2_BUNDLE="$HOSPITAL_RUN_OUTPUT/nav2-profile/hospital_floor_transitions.yaml"
export HOSPITAL_NAV2_DEFAULTS="$HOSPITAL_RUN_OUTPUT/nav2-profile/hospital_nav2_plan_defaults.yaml"
export HOSPITAL_NAV2_PROFILE="$HOSPITAL_RUN_OUTPUT/nav2-profile/run_profile_manifest.json"
test -s "$HOSPITAL_NAV2_PROFILE"
```

The profile generator verifies that the RAG and map manifests refer to the same DSG. Free portal cells do not prove route connectivity; run the Nav2 plan-only check on this bundle before accepting the new transitions.

## 5. Run one frozen Nav2 mission in plan-only mode
