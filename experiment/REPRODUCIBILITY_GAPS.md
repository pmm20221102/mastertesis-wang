# Full Reproduction Gaps: Khronos to Nav2 Planning

This note describes what is still needed to reproduce the Hospital P1000 software pipeline **starting with the raw TartanGround data, running Khronos, and ending with a Nav2 plan**. It complements [`CODE_REPRODUCTION.md`](CODE_REPRODUCTION.md), whose runnable path starts from an already available Hospital DSG and review CSV. This is a software planning workflow: a successful plan does not demonstrate physical robot motion or physical safety.

## Target artifact flow

```text
Hospital P1000 TartanGround source data + calibration/semantic inputs
  -> ROS 2 bag + bag audit
  -> Khronos run
  -> Hospital DSG (dsg.json) + mesh (mesh.ply) + provenance/logs
       |                               |
       |                               +-> Khronos-only map generation
       +-> reviewed semantic CSV          -> floor maps + map manifest
             -> reproducible RAG index
                  -> Ollama-backed task planning
                       + RAG index + map bundle + isolated Nav2 stack
                       -> plan-only result JSON
```

The latest branch (`529f89f`) documents the raw-data path, a fresh RAG/map/profile packager, a bundled interactive GUI, and a task-chain/Nav2 batch path. The GUI and artifacts are packaged, but the current WSL host lacks Ollama, the no-review RAG cannot resolve the bed example, and the batch output lacks run-level input provenance. These limits prevent claiming a reproducible fresh LLM-to-Nav2 result from this checkout.

## New branch review findings

The score path `score_taskchain_benchmark.score_run` is not runnable from this checkout as written. Its default gold file is `experiment/task-chain-60/sealed/gold.jsonl`, which is absent, and the tracked `artifact_manifest.json` has no `sealed_gold_sha256`. The function compares the supplied gold hash to that missing field, so every supplied gold file is rejected. The documented `score_predictions.py` path uses the public `reference/taskchain_gold.jsonl` and remains separate; the run-level scorer needs a matching sealed-gold artifact and manifest hash or a different documented contract.

`package_nav2_run.py` copies the transition template and replaces floor map paths/hashes, but leaves `source_root` unchanged. `hospital_floor_mosaic.py` uses `bundle.source_root/dsg_topology_repaired.json` when no explicit `dsg_path` is supplied. A freshly packaged bundle therefore makes the mosaic label layer read the template's historical DSG unless the caller overrides `dsg_path` or the packager updates `source_root` to the run's derived DSG.

`run_nav2_batch.py` writes per-task missions/results/logs and `summary.json`, but no run manifest with prediction-file, graph, defaults, bundle, and runner hashes. That summary alone cannot identify the full inputs and code used for a later audit or comparison.

6. **Nav2 plan record:** the guide documents the fresh bundle, defaults, Ollama installation/startup, and plan-only commands.
