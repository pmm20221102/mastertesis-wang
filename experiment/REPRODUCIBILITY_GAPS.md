# Full Reproduction Gaps: Khronos to Nav2 Planning

This note describes what is still needed to reproduce the Hospital P1000 software pipeline **starting with the raw TartanGround data, running Khronos, and ending with a Nav2 plan**. It complements [`CODE_REPRODUCTION.md`](CODE_REPRODUCTION.md), whose runnable path starts from an already available Hospital DSG and review CSV. This is a software planning workflow: a successful plan does not demonstrate physical robot motion or physical safety.

## Target artifact flow

```text
Hospital P1000 TartanGround source data + calibration/semantic inputs
  -> ROS 2 bag + bag audit
  -> Khronos run
  -> Hospital DSG (dsg.json) + mesh (mesh.ply) + provenance/logs
       |                               |
       |                               +-> Khronos-only map generation
       +-> reviewed semantic CSV          -> floor maps + map manifest
             -> reproducible RAG index
                  -> Ollama-backed task planning
                       + RAG index + map bundle + isolated Nav2 stack
                       -> plan-only result JSON
```

The map and RAG branches consume artifacts from the same Khronos run. The current checkout documents these branches separately and does not connect them into one executable procedure.

## Reproduction Evidence on the Current Host

The `tartanairpy` downloader was cloned at revision `158a6844d782942110967325ca3082f50ab2bfc7` and installed as package version 1.4.0 in a separate Python 3.12 environment. Its unpinned dependencies resolved to PyTorch 2.14.1 and a CUDA 13 runtime even though the downloader itself uses CPU. The [official TartanGround installation instructions](https://tartanair.org/tartanground.html) document a Python 3.9-tested environment; the repository should pin and document a minimal downloader environment rather than relying on an unpinned editable install.

The adapter source package initially failed to build because `setup.py` referenced a missing `resource/tartanground_khronos_bridge` marker; after adding the marker, `ros2 run` still could not find entry points because `setup.cfg` did not direct scripts into `lib/<package>`. This branch adds both packaging files and installs all launch-referenced configs. Path-portability tests report 2 passed. With `TARTANGROUND_ROOT`, `TARTANGROUND_CONFIG`, and `TARTANGROUND_BAG` set to host-local paths, the adapter suite reports 20 passed and 2 skipped. The Nav2 package also lacked a declared dependency for the configured `nav2_navfn_planner` plugin; this branch now declares it in `package.xml`.

All declared ROS dependencies pass `rosdep check` after installation. Restoring the two C++ sources and five headers fixes the root ignore-rule omission. At commit `2421977`, a complete `colcon build --base-paths src --cmake-args -DCMAKE_BUILD_TYPE=Release` finished all 26 packages with zero failures. This validates the current source build, but it does not recreate historical DSG output because the recorded source revision is unavailable and its working tree was dirty.

The fresh-artifact workflow is now verified on the locally available `fine_full_p1000` DSG/mesh. A reproducible RAG build without a review CSV generated 6,297 documents plus `canonical_graph_v2.json`; `plan_nav2.verify_rag_build` accepted the manifest when its run profile pinned the actual DSG hash and `semantic_review_csv_sha256: null`. Map generation with `--no-manual-topology` produced and recomputed four floor maps from that same DSG and mesh. These checks validate the generic interfaces; the newer DSG/mesh generated on the other computer were not present in this checkout and were not inputs to these local runs. The generated artifacts are under `/tmp/thesis-final-rag-native-topology-v2/` and `/tmp/thesis-final-fresh-map-native-topology-2/`, outside Git.

A full new Khronos run used the audited local bag at `--rate 1.0`, `ROS_DOMAIN_ID=78`, `use_gt_semantics:=true`, and `start_visualizer:=false`. The final graph includes agent timestamps through 318.5 s, consistent with full coverage of the 317.7 s bag, and the run log contains no TF pose-drop diagnostic. After bag playback completed, sending SIGINT to the launch caused Khronos to write the final `dsg.json`, `mesh.ply`, `final.4dmap`, and six floor-time DSG snapshots. The final DSG parses as JSON; the PLY header reports 482,839 vertices and 675,993 faces. The node peaked at roughly 47 GiB RSS and used about 4.5 GiB swap. The launch emitted a `/tf_static` QoS durability warning because the bag's recorded QoS profile is empty; the launch itself publishes the required static transforms, so the run still completed. The run log says `Git repository not found` because Khronos looked for `src/khronos` relative to the launch CWD; the commit must be recorded separately or that provenance lookup documented.

The run's `output_dir` stores experiment config, logs, timing files, and the final DSG/mesh, while `snapshots/` is relative to the launch process's current working directory. Starting the launch from the repository root therefore writes a large ignored `snapshots/` tree at the repository root. The guide should create and enter a run-specific working directory before launching. It should also explicitly send SIGINT to the mapper after bag playback; without shutdown, the final experiment export is not written.

The Khronos-only map generator was invoked with the new DSG and mesh and failed at its first hard-coded manual topology link: Place ID `8070450532247988661` is absent from this DSG. Existing committed maps remain usable for the archived HC-001 plan-only smoke test, but a fresh DSG-to-map-to-Nav2 run is not established until the topology overrides are reconciled with the new graph and the resulting maps are validated.

The separate Nav2 smoke test uses the committed maps and archived mission `HC-001`; it is not an LLM/RAG-to-Nav2 run. Its successful plan-only JSON is `/tmp/HC-001-plan-only.json`.
